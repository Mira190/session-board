## 1. Claude Code local: hooks (events, payloads, HTTP hooks, settings locations)

### Takeaway
Hooks are the best push-style signal for local Claude Code: 33 documented events, a common stdin JSON carrying `session_id`, `transcript_path`, `cwd`, and a native `http` handler type that POSTs the same JSON to a URL, so a session manager can receive events without shipping a script. A `PermissionRequest` hook (command or http) can allow/deny a permission prompt from outside, which is the only documented way to answer a prompt of a running interactive session programmatically.

### Cited Findings
- Hook events (verbatim list, 33): `SessionStart`, `Setup`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `MessageDisplay`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult`, `SessionEnd`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- When they fire (selected): `SessionStart` "When a session begins or resumes"; `UserPromptSubmit` "When a prompt is submitted, before Claude processes it. Also fires on turns Claude Code starts on its own"; `PermissionRequest` "When a tool call needs a permission decision"; `Notification` "When Claude Code sends a notification"; `Stop` "When Claude finishes responding"; `StopFailure` "When the turn ends due to an API error"; `SessionEnd` "When a session terminates". — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Common stdin fields on all events: `session_id`, `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `effort`, `hook_event_name`; plus `agent_id`, `agent_type` when inside a subagent. `permission_mode` values: `"default"`, `"plan"`, `"acceptEdits"`, `"auto"`, `"dontAsk"`, `"bypassPermissions"`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Per-event extra input fields:
  - `SessionStart`: `source` (`"startup"`, `"resume"`, `"clear"`, `"compact"`, `"fork"`), optional `model`, `agent_type`, `session_title`; on resume/fork also `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired`, `estimated_cache_write_usd` (v2.1.251+).
  - `UserPromptSubmit`: `prompt` (and `session_title` when a custom title exists).
  - `PreToolUse`: `tool_name`, `tool_input`, `tool_use_id`. `PostToolUse`: adds `tool_response`, optional `duration_ms`.
  - `PermissionRequest`: `tool_name`, `tool_input` (no `tool_use_id`), optional `permission_suggestions` array.
  - `Notification`: `message`, optional `title`, `notification_type`.
  - `Stop`: `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`. Docs: the two arrays "let hooks distinguish \"session is done\" from \"session is paused waiting for background work to wake it back up\"". `background_tasks[]` fields: `id`, `type` (`shell`, `subagent`, `monitor`, `workflow`, `teammate`, `cloud session`, `MCP task`), `status`, `description`, `command`, `agent_type`, `server`, `tool`, `name`.
  - `StopFailure`: `error` (`rate_limit`, `authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `billing_error`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `cloud_credential_error`, `unknown`), optional `error_details`, optional `last_assistant_message`.
  - `SubagentStop`: `stop_hook_active`, `agent_id`, `agent_type`, `agent_transcript_path` (subagent transcript in a nested `subagents/` folder, e.g. `~/.claude/projects/.../abc123/subagents/agent-def456.jsonl`), `last_assistant_message`, plus `background_tasks`, `session_crons`.
  - `TaskCreated` / `TaskCompleted`: `task_id`, `task_subject`, optional `task_description`, `teammate_name`, `team_name`. `TeammateIdle`: `teammate_name`, `team_name`.
  - `PreCompact`: `trigger`, `custom_instructions`. `PostCompact`: `trigger`, `compact_summary`.
  - `SessionEnd`: `reason` — `clear`, `resume`, `logout`, `prompt_input_exit`, `other` (`bypass_permissions_disabled` removed in v2.1.234).
  — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Matcher values: `Notification` — `permission_prompt`, `idle_prompt`, `auth_success`, `auth_storage_failure`, `elicitation_dialog`, `elicitation_url_dialog`, `elicitation_complete`, `elicitation_response`, `agent_needs_input`, `agent_completed`, `quota_auto_resume_fired`, `quota_auto_resume_stale`, `quota_auto_resume_disabled`, `plugin_notification`. `SessionStart` — `startup`, `resume`, `clear`, `compact`, `fork`. `PreCompact`/`PostCompact` — `manual`, `auto`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Example Notification payload: `{"session_id":"abc123","transcript_path":"/Users/.../.claude/projects/.../00893aaf-19fa-41d2-8238-13269b9b3ca0.jsonl","cwd":"/Users/...","hook_event_name":"Notification","message":"Claude needs your permission","notification_type":"permission_prompt"}`. "Notification hooks can't block or modify notifications." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Handler types: five — `command`, `http`, `mcp_tool`, `prompt`, `agent`. Common fields: `type`, `if`, `timeout`, `statusMessage`, `once`. Default timeouts: 600 s for `command`/`http`/`mcp_tool`, 30 s `prompt`, 60 s `agent`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- HTTP hook fields: `url` (required; "the URL that receives the POST"), `headers` (values support `$VAR_NAME`/`${VAR_NAME}` interpolation), `allowedEnvVars` (unlisted references become empty strings), `onFailure` (`"continue"` or `"block"`). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Command hook fields: `command`, `args`, `async`, `asyncRewake`, `shell` (`"bash"`/`"powershell"`), `onFailure`. `async: true` runs in background without blocking; `asyncRewake: true` wakes Claude on exit code 2. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Handler-type restrictions: "`Setup` supports only `command` hooks. `SessionStart` supports only `command` and `mcp_tool` hooks". "`PermissionRequest` supports `command`, `http`, `mcp_tool`, and `prompt` hooks but not `agent` hooks ... To allow or deny from a hook, return the decision object from a command or HTTP hook." A group of events including `Notification`, `SessionEnd`, `StopFailure`, `SubagentStart`, `PreCompact`, `PostCompact` appears in a restricted-handler list (exact rule text not captured; see Gaps). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- `PermissionRequest` decision output: `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{...}}}}`. Fields in `decision`: `behavior` (`"allow"`/`"deny"`), `updatedInput` (allow only), `updatedPermissions` (allow only; entry types `addRules`, `replaceRules`, `removeRules`, `setMode`, `addDirectories`, `removeDirectories`), `message` (deny only), `interrupt` (deny only; `true` stops Claude). Exit code 2 is not honored for this event. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Exit codes: 0 = success (stdout JSON object applied); 2 = blocking error on events that can block; other = non-blocking error. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Hook config locations: `~/.claude/settings.json` (all projects), `.claude/settings.json` (project, committed), `.claude/settings.local.json` (project, gitignored), managed policy settings, plugin `hooks/hooks.json`, skill frontmatter, subagent frontmatter. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Hooks do not run under `--bare`; without `--bare`, `claude -p` runs project hooks even in an untrusted folder. — [Headless docs](https://code.claude.com/docs/en/headless)
- On SIGTERM a `claude -p` run "runs `SessionEnd` hooks and exits" with code 143. — [Headless docs](https://code.claude.com/docs/en/headless)

### Inferences
- Minimal adapter hook set for a state machine: `SessionStart` (register), `UserPromptSubmit` (-> working), `Notification` with matchers `permission_prompt` / `idle_prompt` / `elicitation_dialog` / `agent_needs_input` (-> needs input), `PermissionRequest` (-> needs approval, and optional remote answer), `Stop` (-> turn done; check `background_tasks`/`session_crons` to tell idle from "paused waiting for background work"), `StopFailure` (-> failed turn), `SessionEnd` (-> closed).
- An `http` hook in `~/.claude/settings.json` pointing at a localhost collector gives discovery plus notifications for every interactive and `-p` session on the machine with one config edit; `session_id` + `transcript_path` + `cwd` are enough to key a session.
- Remote permission answering can be built by making the `PermissionRequest` http hook block (up to its 600 s default timeout) while the session manager asks the user, then returning the `decision` object. This is an inference from the documented fields; the docs describe the mechanism but not this specific pattern.
- A hard kill (SIGKILL, crash, power loss) cannot fire `SessionEnd`; liveness needs a second signal (PID from `claude agents --json`, or transcript mtime).

### Gaps
- HTTP hook response handling (status-code semantics, response body parsing, retry) was not captured; the relevant section of the hooks page was not read. Only the `WorktreeCreate` http example (return `hookSpecificOutput` in the response body) was seen.
- The exact rule attached to the list of events containing `Notification`/`SessionEnd`/`StopFailure`/... (likely "these events support only command/http/mcp_tool handlers") is UNVERIFIED.
- Input fields for `MessageDisplay`, `Elicitation`, `PermissionDenied`, `PostToolBatch` were not captured.
- Hook env vars (`CLAUDE_PROJECT_DIR`, `CLAUDE_ENV_FILE` were seen in examples; `CLAUDE_CODE_REMOTE` not confirmed this session).

## 2. Claude Code local: transcripts, headless mode, background sessions, Agent SDK

### Takeaway
Three complementary surfaces exist: a documented-location but explicitly unstable JSONL transcript; headless `claude -p` with `stream-json` for sessions the manager spawns itself; and the research-preview background-session supervisor (`claude --bg`, `claude agents --json`) which exposes an official machine-readable state (`working`/`blocked`/`done`/`failed`/`stopped` + `waitingFor`). The Agent SDK adds `listSessions()`/`getSessionMessages()` and a `canUseTool` permission callback.

### Cited Findings
- Transcript location: "`~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your working directory path with non-alphanumeric characters replaced by `-`" (e.g. `/Users/me/proj` -> `-Users-me-proj`); names over 200 chars are truncated plus a hash. Overrides: `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_PROJECT_DIR_NAME`. Retention default 30 days via `cleanupPeriodDays`. — [Manage sessions](https://code.claude.com/docs/en/sessions); [Agent SDK sessions](https://code.claude.com/docs/en/agent-sdk/sessions)
- Transcript format stability: "Each line is a JSON object: a message, a tool use or result, a record of a request Claude Code sent the model, or a metadata entry. The entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release." — [Manage sessions](https://code.claude.com/docs/en/sessions)
- At `Stop` time "the transcript file isn't guaranteed to include the final message ... on all versions"; use `last_assistant_message`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Transcript writes can be suppressed: `CLAUDE_CODE_SKIP_PROMPT_HISTORY`, `--no-session-persistence` (with `-p`), SDK `persistSession: false`. — [Manage sessions](https://code.claude.com/docs/en/sessions); [Agent SDK sessions](https://code.claude.com/docs/en/agent-sdk/sessions)
- Documented script interfaces ("Access conversations from scripts"): `claude -p` with `--output-format json|stream-json`; `claude -p --resume <session-id>`; `transcript_path` from hooks/status line; Agent SDK. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Headless: `-p`/`--print`; `--output-format text|json|stream-json`; streaming needs `--output-format stream-json --verbose --include-partial-messages`; `--input-format stream-json`; `--json-schema`; `--continue`; `--resume <session-id>` (or absolute `.jsonl` path; works from any directory); `--fork-session`; `--permission-mode`; `--allowedTools`; `--permission-prompt-tool`; `--permission-prompts none` (v2.1.259+); `--max-budget-usd`; `--bare`; `--settings`; `--mcp-config`. — [Headless docs](https://code.claude.com/docs/en/headless)
- stream-json events: first `system/init` (model, tools, `mcp_servers`, `plugins`, optional `capabilities` such as `interrupt_receipt_v1`); `assistant` / `user` messages with `parent_tool_use_id` (null for main conversation); `stream_event` (with `.event.delta.type == "text_delta"`); `system/api_retry` (`attempt`, `max_retries`, `retry_delay_ms`, `error_status`, `error`, `uuid`, `session_id`); `system/plugin_install`; `hook_started`/`hook_progress`/`hook_response`; `permission_denied` system messages; last line is a `result` message with final text, cost, session metadata and `permission_denials`. `--output-format json` returns `result`, `session_id`, `total_cost_usd`, optional `structured_output`. — [Headless docs](https://code.claude.com/docs/en/headless)
- Exit behaviour: exit 0 on success, non-zero on failure; SIGTERM -> exit 143 with unfinished turn; SIGINT or SDK `interrupt()` ends the turn. In a `-p` run with no permission host, calls needing approval are denied unless a `PermissionRequest` hook or `--permission-prompt-tool` approves. — [Headless docs](https://code.claude.com/docs/en/headless)
- Sessions created by `claude -p` or the Agent SDK are hidden from the session picker and `claude --continue`, but resumable by ID. Two processes resuming the same session write to one transcript and can lose messages; use `--fork-session`. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Background sessions / agent view (research preview): `claude --bg "<prompt>"`, `claude --bg --name <n>`, `claude --resume <session-id> --bg "..."`, `claude agents`, `claude agents --json [--all] [--cwd <path>]`, `claude attach <id|name>`, `claude logs <id|name>`, `claude stop <id>` (alias `claude kill`), `claude respawn <id>`, `claude rm <id>`, `claude daemon status|logs|stop`. `--bg` cannot be combined with `-p`. — [Agent view](https://code.claude.com/docs/en/agent-view)
- `claude agents --json` entry fields: `cwd`, `kind` (`interactive` or `background`), `startedAt` (Unix ms) always; `id` and `state` (`working`, `blocked`, `done`, `failed`, `stopped`) for background sessions; `pid`, `status` (`busy`, `waiting`, `idle`) while the process is alive; `waitingFor` (`permission prompt`, `input needed`, `sandbox request`, `worker request`, `dialog open`) when `status` is `waiting`; `sessionId` (full UUID usable with `claude --resume`) and `name` when set. Docs tell scripts to poll `claude agents --json --all` and not to parse `~/.claude/jobs/`. — [Agent view](https://code.claude.com/docs/en/agent-view)
- UI states: Working, Needs input, Idle, Completed, Failed, Stopped (`blocked` is labelled "Needs input"; `done` is "Completed"). On-disk state: `~/.claude/daemon/roster.json`, `~/.claude/jobs/<id>/state.json` ("not a stable interface"), `~/.claude/daemon.log`. Disable with `disableAgentView` / `CLAUDE_CODE_DISABLE_AGENT_VIEW`. — [Agent view](https://code.claude.com/docs/en/agent-view)
- Sending a message to a running background session from the shell: `claude --resume <session> "check the tests too"` sends the prompt as the session's next turn then attaches ("Sent your prompt to the background session (<id>); opening it…"); it is refused with piped I/O or flags such as `--output-format json`, and a prompt is not sent "while the session waits on your answer to a question". Peek replies in agent view "do not answer dialogs"; permission prompts need an attach. — [Manage sessions](https://code.claude.com/docs/en/sessions); [Agent view](https://code.claude.com/docs/en/agent-view)
- Agent SDK: packages `@anthropic-ai/claude-agent-sdk` (TS) and `claude_agent_sdk` (Python); `query()` options `continue`, `resume`, `forkSession`/`fork_session`, `persistSession`, `sessionStore`/`session_store`; Python `ClaudeSDKClient`; session ID on init `SystemMessage` and on every `ResultMessage.session_id`; result subtypes include `success`, `error_max_turns`, `error_max_budget_usd`; enumeration `listSessions()`/`list_sessions()`, `getSessionMessages()`/`get_session_messages()`, `getSessionInfo()`, `renameSession()`, `tagSession()`. The experimental V2 `createSession()` API "was removed in TypeScript Agent SDK 0.3.142". Permission prompts and `AskUserQuestion` are handled in-loop via the `canUseTool` callback. — [Agent SDK sessions](https://code.claude.com/docs/en/agent-sdk/sessions); [Headless docs](https://code.claude.com/docs/en/headless)

### Inferences
- Reliability ranking for observing sessions the manager did not start: hooks (documented, push) > `claude agents --json` (documented, poll, research preview, richest state incl. `waitingFor`) > transcript tailing (location documented, format explicitly unstable).
- For sessions the manager spawns: `claude --bg` gives a supervised, attachable, listable session; `claude -p --output-format stream-json` or the Agent SDK gives full event streaming and a programmatic permission callback but the session is invisible to the interactive picker.
- There is no documented general-purpose "inject a message into someone else's interactive TUI session" API. Documented routes are: background-session prompt via `claude --resume <id> "..."` from a TTY, Remote Control (web/mobile clients only), and hooks that return context/decisions.

### Gaps
- `--session-id <uuid>` for pre-assigning a session ID on a new `claude` run was not confirmed this session (it appears on the Remote Control server flags with different meaning). UNVERIFIED for plain `claude`.
- `--permission-prompt-tool` protocol details (MCP tool input/output shape) not read.
- Field list returned by `listSessions()` (e.g. `sessionId`, `summary`, `lastModified`, `cwd`, `gitBranch`) UNVERIFIED; the TS reference page was not read.
- Whether `claude agents --json` lists plain interactive sessions when the supervisor is not running was not checked (docs say `kind` can be `interactive`).
- "Channels" (docs page `channels`) is mentioned as a way runs can be started; not researched.

## 3. Claude Code local: OpenTelemetry and Remote Control

### Takeaway
OTel export is documented and env-var driven, with `session.id` on every metric/event and beta traces; it is good for metering and audit but has no explicit "session state" signal. Remote Control is a first-party relay (outbound HTTPS only) for claude.ai/code and the mobile app with no public third-party API.

### Cited Findings
- Enable: `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER` (`otlp`, `prometheus`, `console`, `none`), `OTEL_LOGS_EXPORTER` (`otlp`, `console`, `none`), `OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_METRIC_EXPORT_INTERVAL` (default 60000 ms), `OTEL_LOGS_EXPORT_INTERVAL` (default 5000 ms); content gates `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_ASSISTANT_RESPONSES`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT`, `OTEL_LOG_RAW_API_BODIES`. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Metrics: `claude_code.session.count`, `claude_code.lines_of_code.count`, `claude_code.pull_request.count`, `claude_code.commit.count`, `claude_code.cost.usage`, `claude_code.token.usage`, `claude_code.code_edit_tool.decision`, `claude_code.active_time.total`. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Events (logs): `claude_code.user_prompt`, `claude_code.assistant_response`, `claude_code.tool_result`, `claude_code.api_request`, `claude_code.api_error`, `claude_code.api_refusal`, `claude_code.api_request_body`, `claude_code.api_response_body`, `claude_code.tool_decision` (list may be incomplete; page truncated). — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Standard attributes: `session.id`, `ccr.session.id`, `app.version`, `app.entrypoint`, `organization.id`, `user.account_uuid`, `user.account_id`, `user.id`, `user.email`, `terminal.type`; event-only: `prompt.id`, `event.sequence`, `event.timestamp`, `message.uuid`, `request_id`, `agent_id`, `parent_agent_id`, `workflow.run_id`. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Traces (beta, off by default): `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` + `OTEL_TRACES_EXPORTER`; spans `claude_code.interaction` (root span per user prompt), `claude_code.llm_request`, `claude_code.tool`, `claude_code.tool.blocked_on_user`, `claude_code.tool.execution`, `claude_code.hook`; `CLAUDE_CODE_PROPAGATE_TRACEPARENT=1`. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Remote Control start modes: `claude remote-control` (server mode), `claude --remote-control` / `--rc`, in-session `/remote-control` / `/rc`. Server flags: `--name`, `--remote-control-session-name-prefix`, `-c/--continue`, `--session-id <id>`, `--spawn <mode>` (`same-dir`, `worktree`, `session`), `--capacity <N>` (default 32), `--[no-]create-session-in-dir`, `--permission-mode`. — [Remote Control](https://code.claude.com/docs/en/remote-control)
- How it works: "Your local Claude Code session makes outbound HTTPS requests only and never opens inbound ports on your machine. When you start Remote Control, it registers with the Anthropic API and polls for work." All traffic goes through the Anthropic API over TLS with short-lived credentials. — [Remote Control](https://code.claude.com/docs/en/remote-control)
- Requirements/limits: claude.ai subscription auth only ("API keys are not supported"); Team/Enterprise need an Owner to enable it; not available with `ANTHROPIC_BASE_URL` pointed elsewhere; "One remote session per interactive process" outside server mode; server mode exits after roughly 10 minutes of network outage; permission prompts and `AskUserQuestion` stay open until answered, other forwarded dialogs expire after five minutes (`dialogExpiry`). — [Remote Control](https://code.claude.com/docs/en/remote-control)
- Mobile push: `/config` -> **Push when Claude decides** / **Push when actions required**; `CLAUDE_CLIENT_PRESENCE_FILE` suppresses pushes while a marker file exists. — [Remote Control](https://code.claude.com/docs/en/remote-control)

### Inferences
- The `claude_code.tool.blocked_on_user` span is the only OTel signal that maps to "waiting for approval"; it is beta and arrives only when the span ends, so OTel is not a good real-time state source. Use hooks for state, OTel for cost/tokens.
- Remote Control answers permission prompts from web/mobile, but the client protocol is private. A third-party session manager cannot use it as a control channel; it can only start it (`claude remote-control`) and deep-link to `claude.ai/code/<id>`.

### Gaps
- No public documentation of the Remote Control wire protocol was found; none is claimed.
- Remainder of the monitoring page (after `claude_code.tool_decision`) not read; additional events may exist.

## 4. Claude Code cloud (Claude Code on the web)

### Takeaway
There is no documented public REST API to list cloud sessions or read their status/events. Documented programmatic surfaces are: creating a session (`claude --cloud "<task>"`), queueing a message into an existing session (`claude -p "msg" --cloud <session-id>`, JSON result `{ok, session_id, url}`), pulling a session local (`--teleport`), and the research-preview scheduled-task `/fire` HTTP endpoint which returns a session ID/URL. Observation is indirect: `claude/`-prefixed branches and PRs on GitHub, in-session hooks, and OTel `ccr.session.id`.

### Cited Findings
- Surfaces that start cloud sessions: claude.ai/code, mobile **Code** tab, Desktop app, `claude --cloud`, cloud scheduled tasks. "`--remote`" is a deprecated alias for `--cloud`. — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)
- Create: `claude --cloud "Fix the authentication bug in src/auth/login.ts"` creates a new cloud session; the VM clones the current directory's GitHub remote at the current branch (or uploads a bundle; `CCR_FORCE_BUNDLE=1`). Each `--cloud` command creates an independent session. — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)
- Send follow-up: `claude -p "your message" --cloud <session-id>` — "The CLI queues the message into the session and exits without waiting for a reply." `<session-id>` may be `session_...`, `cse_...`, or the `claude.ai/code/<id>` URL. `--output-format json` gives `{ok, session_id, url}` or `{ok: false, session_id, error}`; "`--output-format stream-json` isn't supported with `--cloud <session-id>`". Errors include `Session not found: <id>` and `cloud session <id> is archived and cannot accept new messages`. — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)
- Pull local: `claude --teleport [<session-id>]`, `/teleport` or `/tp`, `/tasks` then `t`. Handoff from the CLI is one-way (cloud -> terminal). "`--resume` ... doesn't list cloud sessions." — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)

## 8. Normalized session state machine implied by these surfaces

### Takeaway
All surfaces converge on roughly the same six-to-eight states: starting, working, waiting-for-input (split into permission vs question vs auth), idle (turn done, session alive), completed, failed, stopped/canceled. A2A's `TaskState` is the closest ready-made vocabulary; the vendor surfaces differ mainly in whether "idle after a turn" is distinguished from "completed".

### Cited Findings
- A2A `TaskState`: `SUBMITTED`, `WORKING`, `INPUT_REQUIRED`, `AUTH_REQUIRED`, `COMPLETED`, `FAILED`, `CANCELED`, `REJECTED`, `UNSPECIFIED`. — [A2A specification](https://a2a-protocol.org/latest/specification/)
- Claude Code agent view: `state` in `working`, `blocked`, `done`, `failed`, `stopped`; `status` in `busy`, `waiting`, `idle`; `waitingFor` in `permission prompt`, `input needed`, `sandbox request`, `worker request`, `dialog open`. — [Agent view](https://code.claude.com/docs/en/agent-view)
- Claude Code hooks: `Notification.notification_type` includes `permission_prompt`, `idle_prompt`, `elicitation_dialog`, `agent_needs_input`, `agent_completed`; `Stop` vs `StopFailure`; `SessionEnd.reason`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Claude scheduled-task run outcomes: Succeeded / Failed / Cancelled ("These outcomes say how the session ended, not whether Claude completed the work"). — [Scheduled tasks (routines)](https://code.claude.com/docs/en/routines)
- Codex app-server: thread status `notLoaded`, `idle`, `systemError`, `active` (+ `activeFlags` e.g. `waitingOnApproval`); turn status `inProgress`, `completed`, `interrupted`, `failed`. — [App server](https://learn.chatgpt.com/docs/app-server)
- Codex exec JSONL: `turn.started`, `turn.completed`, `turn.failed`, `error`. Codex hooks `PostModelRequest.status`: `completed`, `failed`, `cancelled`. — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode); [Codex hooks](https://learn.chatgpt.com/docs/hooks)
- ACP: `StopReason` `end_turn`, `max_tokens`, `max_turn_requests`, `refusal`, `cancelled`; pending `session/request_permission`; `ToolCallStatus` `pending`, `in_progress`, `completed`, `failed`. — [ACP schema](https://agentclientprotocol.com/protocol/schema)
- AG-UI: RunStarted / RunFinished (with optional interrupt `outcome`) / RunError. — [AG-UI events](https://docs.ag-ui.com/concepts/events)

### Inferences
- Proposed mapping (normalized state <- vendor signals):

| Normalized (A2A-like) | Claude Code local | Codex local | ACP | Cloud (either) |
|---|---|---|---|---|
| submitted / starting | `SessionStart` hook; `system/init` | `SessionStart` hook; `thread.started`; `thread/started` | `session/new` returned | spawn call returned session/task id |
| working | `UserPromptSubmit`, `PreToolUse`; agents `state=working`/`status=busy` | `UserPromptSubmit`; `turn.started`; thread `active`, turn `inProgress` | `session/prompt` in flight, `session/update` flowing | inferred (no API) / `codex cloud list --json` |
| input-required: permission | `PermissionRequest` hook; `Notification` `permission_prompt`; `waitingFor="permission prompt"` | `PermissionRequest` hook; `item/*/requestApproval`; `activeFlags` `waitingOnApproval` | `session/request_permission` pending | not observable via documented API |
| input-required: question | `Notification` `idle_prompt` / `elicitation_dialog` / `agent_needs_input`; `waitingFor="input needed"` | `item/tool/requestUserInput`; `mcpServer/elicitation/request` | `elicitation/create` | not observable |
| auth-required | `Notification` `auth_success`/`auth_storage_failure` (partial) | `codexErrorInfo` `unauthorized` | `authenticate` needed | — |
| idle (turn done, alive) | `Stop` with empty `background_tasks`; `status=idle` | `Stop` hook; `notify` `agent-turn-complete`; thread `idle`, turn `completed` | `StopReason` `end_turn` | — |
| completed | agents `state=done`; `result` subtype `success`; `SessionEnd` | `turn.completed` then process exit (exec) | session closed after `end_turn` | PR opened / run "Succeeded" |
| failed | `StopFailure`; `state=failed`; `result` error subtypes | `turn.failed`, `error`; thread `systemError`; turn `failed` | `refusal`, `max_tokens`, `max_turn_requests`, JSON-RPC error | run "Failed" |
| canceled / stopped | `state=stopped`; SIGTERM exit 143; `SessionEnd` | `Interrupt` hook; turn `interrupted` | `StopReason` `cancelled` | run "Cancelled" |

- The interactive-CLI world needs one state A2A lacks: "idle" (turn finished, session still open and resumable). A session manager should keep `idle` distinct from `completed`, and treat `completed` as a property of spawned/background/cloud runs only.
- "Working but paused on background tasks" (Claude `Stop` with non-empty `background_tasks`/`session_crons`) is a Claude-specific sub-state worth preserving as working/waiting-on-self rather than idle.

### Gaps
- No single primary source defines a cross-vendor state machine; the mapping table above is an inference from the cited enums.
- Edge transitions not verified empirically: e.g. whether Claude `Notification` `idle_prompt` always follows `Stop`, the idle threshold, or whether Codex `Stop` fires on interrupted turns in addition to `Interrupt`.
